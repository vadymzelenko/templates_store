# Booking Engine — універсальний рушій записів (Next.js + Supabase + magic link)

Лендинг із формою запису → лист із magic link (nodemailer) → підтвердження + автоматичний вхід у кабінет.
Профіль клієнта (змінити / видалити запис), CRM для власника (записи, статуси, перенесення, видалення, журнал).
Паролів немає ні в клієнтів, ні у власника.

## Швидкий старт
1. `npm install`
2. Supabase → SQL Editor → виконати `supabase/schema.sql`
3. `cp .env.example .env.local` і заповнити (`PUBLIC_BASE_URL`, `JWT_SECRET`, `ADMIN_EMAIL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`)
4. `npm run dev` → http://localhost:3000

З `EMAIL_PROVIDER=console` (або без Gmail-даних) magic link друкується в консоль сервера — тестувати можна без пошти.
Власник входить так само: кнопка «Профіль клієнта» → його пошта з `ADMIN_EMAIL` → лист → потрапляє в `/admin`.

## Архітектура: що де лежить

### Папка `business/` — єдине, що міняється під нову нішу
| Файл | За що відповідає |
|---|---|
| `business/fields.js` | Поля форми та структура даних (що з'явиться колонками в БД) |
| `business/rules.js` | Логіка: години, слоти, вихідні, статуси, чи можна клієнту змінювати запис |
| `business/texts.js` | Усі тексти інтерфейсу та листів, мова |
| `business/landing.js` | Контент лендингу: hero, послуги й ціни, кроки, адреса, FAQ |
| `business/theme.js` | Бренд, кольори, шрифт |

### База даних
- `db/base.sql` — універсальна основа (3 таблиці), не змінюється.
- `npm run db:sql` збирає `supabase/schema.sql` = основа + view `bookings_readable` + індекси з `fields.js`.
  Цей view показує кожне поле форми окремою колонкою в Table Editor Supabase. Дані не чіпаються, запускати можна скільки завгодно.
- Нові поля не вимагають міграцій: усе, що не є службовою колонкою, лежить у `bookings.data` (jsonb).

### Стилі (`styles/`)
| Файл | Що стилізує |
|---|---|
| `base.css` | змінні, кнопки, поля форм, модалка, бейджі (спільне) |
| `landing.css` | лендинг: hero, прайс, кроки, запис, FAQ, футер |
| `crm.css` | записи: кабінет клієнта (картки) і таблиця/журнал власника |
| `admin_page.css` | каркас сторінки `/admin`: заголовок, вкладки, фільтри |
| `message_email.js` | вигляд листа з magic link (inline-стилі, CSS у листах не працює) |

### Ядро (не чіпати)
`lib/*` (логіка, auth, сесія, пошта), `app/api/*`, `components/*`, `engine.config.js` (збирає `business/*`).

## Нова ніша за 5 хвилин
Дай ШІ вміст `AI_PROMPT.md` + файли з `business/` + опис бізнесу. Він поверне нові `business/*.js`.
Потім: `npm run db:sql` і виконати `supabase/schema.sql`.

## Безпека
- Токен у БД лише як sha256, одноразовий, 15 хв; ліміт 1 лист/хв на пошту.
- Токен гаситься POST-запитом зі сторінки `/auth/verify` (поштові сканери не «спалюють» посилання).
- RLS увімкнено без політик: браузер не має прямого доступу до БД, тільки сервер через service_role.
- `/admin` і `/api/admin/*` перевіряють пошту по `ADMIN_EMAIL` при кожному запиті.

## Відомі обмеження (на потім)
- Перевірка зайнятості слота робиться в коді, не в БД: при одночасному кліку двох людей можливий гонковий збіг (при підтвердженні перевіряється ще раз).
- Ліміт листів лише по пошті; для продакшену додай ліміт по IP (Upstash/Vercel KV).
- `pending`-записи, що не підтвердили, лишаються в БД (слот вони звільняють через `pendingHoldMinutes`); можна додати cron-очищення.
